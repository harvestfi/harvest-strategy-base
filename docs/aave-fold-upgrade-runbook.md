## Transaction Builder: read this once

Every Safe step loads a JSON file into Safe{Wallet} → Apps → Transaction Builder (drag the file in). The files list the **raw inner calls**. For a 2-call file, Builder itself wraps them in a delegatecall to MultiSendCallOnly `0x9641d764…`. Never paste a pre-encoded `multiSend(bytes)` call into Builder: it would send it with operation 0, the inner calls would run with `msg.sender` = the MultiSend contract, and governance-only calls would revert.

Builder may show a checksum or "modified" warning when importing these files: expected, they are generated by the scripts, not exported from Builder. What counts is the decoded view.

Before signing, check Builder's decoded view against the step below (target, value 0, call count).

Every `*_TX=` hash passed to a check script is the Safe **execution** tx hash (the on-chain tx that called `execTransaction`), not the `safeTxHash` shown while collecting signatures. The checks require the Safe's `ExecutionSuccess` event in that receipt and fail otherwise.

## Phase 2: strategy upgrade (live NAV + premium-free flashloans; 12 h timelock)

Prerequisite: the strategy-only rehearsal (`test/aave/fold/upgrade-rehearsal-fork.js`) green with `REHEARSAL_BLOCK` after the Phase 0 transactions (any block > 53112300). Evidence: 13/13, entry 27.2 bp, exit −12.1 bp, including "keeper against the new impl": a fresh `KeeperChecker` wired as the Safe reads the new impl's `checker()` within `checkGasLimit` (`NOT_NEEDED` while healthy) and runs its Morpho deleverage through the new pool inside the 4.5M per-entry cap.

**2.1 Deploy (deployer EOA):**
```bash
npx hardhat run scripts/16-prepare-fold-upgrade.js --network mainnet
```
Strategy-only is the default (`STRATEGY_ONLY=1` is still accepted and changes nothing). The old strategy + vault path runs only with `LEGACY_VAULT_UPGRADE=1`; any other value of it, `STRATEGY_ONLY` set to anything but `1`/`true`, both set, or `VAULT_IMPL` set in strategy-only mode exits 1 before anything is deployed.

Deploys and Basescan-verifies the new `AaveReserveLib` and the strategy impl linked to it; nothing for the vault. It exits 1 before printing any governance step if a library's bytecode is not this build's (supplied, fresh, or the one embedded in the impl), or if the impl's runtime code is not byte-for-byte this build's strategy with that library linked. It prints the impl's linked library and the plan below, and writes (the file list is `strategyOnlyFiles()` in `scripts/fold-upgrade-plan.js`, the same txs the rehearsal executes):

| file | content |
|---|---|
| `out/safe-tx-1-schedule.json` | 1 call: `scheduleUpgrade(<impl>)` (`0x0c80447a…`) on `0xcfd2…` |
| `out/safe-tx-2-upgrade.json` | 2 calls on `0xcfd2…`: `preInteract()` `0xbd51aa1c`, then `upgrade()` `0xd55ec697` |
| `out/safe-rollback-schedule.json` | 1 call: `scheduleUpgrade(0x74ae6e11a89ae6dfe3a304f7881b67a93187ed3f)` on `0xcfd2…` |

If verification failed (propagation delay), re-run without redeploying:
```bash
AAVE_RESERVE_LIB=<lib> STRATEGY_IMPL=<impl> VERIFY_REUSED=1 \
  npx hardhat run scripts/16-prepare-fold-upgrade.js --network mainnet
```
A reused `STRATEGY_IMPL` must match this build exactly (library address aside), or the script exits 1 before doing anything. With `STRATEGY_IMPL` but no `AAVE_RESERVE_LIB`, the library linked into that impl is used (never a fresh one).
- [ ] Basescan: the impl's linked library is the **new** one, not `0x2B19aB8A…`.

**2.2 Safe tx 1:** Transaction Builder, `safe-tx-1-schedule.json`. Decoded view: exactly one call to `0xcfd2…`, value 0.

**2.3 Check:**
```bash
STRATEGY_IMPL=<impl> SCHEDULE_TX=<Safe exec tx hash> node scripts/fold-upgrade-check.js --phase after-schedule
```
Asserts the receipt carries the Safe's `ExecutionSuccess` (and no `ExecutionFailure`), `nextImplementation() == impl`, `nextImplementationTimestamp() ==` the tx's block timestamp + 43200, the vault's `nextImplementation() == 0`, that the impl's code does not contain the stale library address `0x2B19…` anywhere, and (from the compiled artifacts) that the impl is byte-for-byte this build and its linked library is this build's. Without artifacts (`npx hardhat compile` on the same commit) the library check **fails**; `SKIP_LIB_CHECK=1` skips only the artifact part, never the stale-address scan. Prints the earliest time for tx 2.

**2.4 Wait > 12 h, then right before signing tx 2:**
```bash
STRATEGY_IMPL=<impl> node scripts/fold-upgrade-check.js --phase before-upgrade
```
Asserts the latest block timestamp is **strictly** greater than `nextImplementationTimestamp()` and the scheduled impl is still right, then prints `EXPECTED_PPFS`, `EXPECTED_PREVIEW_REDEEM` and `EXPECTED_PPFS_AT` (the read's timestamp): the vault's share price with the new impl, via an `eth_call` `stateDiff` override of the strategy proxy's impl slot. The share price **moves inside tx 2 by design** (the old impl's cached NAV catches up with live NAV, net of the fee it books). That override value is the reference, not the rehearsal's −7.6 bp.

**2.5 Safe tx 2:** Transaction Builder, `safe-tx-2-upgrade.json`. Builder must show a delegatecall to `0x9641d764…` with the two inner calls in this order. It must be **one** batch: `preInteract()` books the fee on the old impl, then `upgrade()` runs `finalizeUpgrade()` (resync, no fee). Unbundled, the fee on any gain since the last interaction is forgiven.

**2.6 Check:**
```bash
STRATEGY_IMPL=<impl> UPGRADE_TX=<tx 2 hash> node scripts/fold-upgrade-check.js --phase after-upgrade
```
Asserts `implementation() == impl`, `nextImplementation() == 0`, `leverFlashPremiumBps() == 0`, `deleverFlashPremiumBps() == 0`, `feeFloor() == 1000`, vault impl still `0x4942b35f…`, `depositCap() == 200e18`, Spectra `getIBTRate() == previewRedeem(1e18) * 1e9`; from the receipt: the Safe's `ExecutionSuccess`, the strategy proxy's `Upgraded(impl)` event, and `implementation()` != impl at `txBlock − 1` and == impl at `txBlock`; and share-price continuity within **0.01 bp with a time-aligned override**: the new-impl override on `txBlock − 1` state, run at `txBlock`'s number and timestamp (`eth_call` block overrides), against `getPricePerFullShare()` at `txBlock`, tolerance max(1 wei, 1e-6 relative) for other txs in the same block. Not 1 wei: the new impl's NAV accrues with `block.timestamp` (≈ −1.5e-8 per 2 s block), so values at different timestamps differ by construction. If the RPC rejects block overrides, the script says so and compares the unaligned override with the same tolerance.

`UPGRADE_TX` is the pass/fail path. `EXPECTED_PPFS=<from 2.4>` (with `EXPECTED_PPFS_AT`) without `UPGRADE_TX` is informational only: it prints the diff in bp and the time elapsed since 2.4, and never fails.
- [ ] First real deposit / withdrawal: ≈ 27 bp in, ≈ −12 bp out.

**Per-transaction deposit limit:** deposits are limited by DEX depth on the new Aero pool (a deposit buys ~12.5× its size in cbETH; one too large reverts on the 50 bp swap floor). Measured ~25 WETH on the fork before Phase 0; the live simulations after Phase 0 passed 0.01–30 WETH (exits ≈ 46.5 bp on the old impl, `withdrawAll()` OK). The limit moves with the pool's depth: re-simulate before quoting users a number. Holds before and after the upgrade.

**Rollback:** Safe `safe-rollback-schedule.json`; check with `STRATEGY_IMPL=0x74ae6e11a89ae6dfe3a304f7881b67a93187ed3f` and the same `--phase after-schedule` / `before-upgrade` (the library check is skipped for that impl); strictly after 12 h, `safe-tx-2-upgrade.json` again (its calls are impl-independent); then `--phase after-upgrade` with `UPGRADE_TX`. In rollback mode the new-impl getters are skipped and the share price across tx 2 is printed (before / after / bp) **without** a pass/fail: the old impl reports a cache, so no override at `txBlock − 1` can match it. The receipt checks (`ExecutionSuccess`, `Upgraded(0x74ae…)`, `implementation()` before/after) still apply. If deposits fail on the lever path: Safe `vault.setInvestOnDeposit(false)`. If exits fail: governance `manualDeleverStep(amount)` in chunks (`emergencyExit()` uses the flash delever, so it is no fallback).
